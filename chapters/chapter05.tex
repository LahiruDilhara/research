\section{Chapter Overview}
\label{sec:test_overview}
Evaluating the paper-based virtual macro keyboard requires testing hand tracking, PyTorch LSTM touch detection, homography stability, CPU latency, and macro command execution \cite{ReviewVirtualKeyboard2020}. Because paper has no physical switches, interaction reliability depends on algorithmic precision: 21-joint skeletal extraction, scale-normalized kinematics, deep sequence modeling, and planar homography \cite{Zhang2020MediaPipe}.

Testing addresses three core challenges: detecting physical surface contact without depth sensors, ensuring invariance across hand sizes and camera distances, and guaranteeing real-time CPU execution at 12~FPS across resolutions without a GPU.

Testing evaluated both Application~1 (Layout Designer) and Application~2 (Runtime Engine). Section~\ref{sec:test_plan_cases} defines functional and non-functional test cases. Section~\ref{sec:test_workflow} outlines the evaluation procedure. Section~\ref{sec:test_results_review} presents quantitative benchmarks covering model architectures, landmark subsets, window configurations, scale normalization, CPU latency, AprilTag tilt resilience, and macro action dispatch. Section~\ref{sec:test_summary} concludes the chapter.

Based on the results in Table~\ref{tab:non_functional_test_cases}, all target non-functional requirements were satisfied:
\begin{itemize}
    \item \textbf{Real-Time Speed and Latency (NFT-01, NFT-02):} The background engine achieved an end-to-end processing latency of $29.09$~ms ($\approx 34.4$~FPS), which is well below the threshold of $83.3$~ms for 12~FPS execution. \end{itemize}

\section{Testing and Evaluation Workflow}
\label{sec:test_workflow}
The testing and evaluation process was conducted across four main phases:
\begin{enumerate}
    \item \textbf{Phase 1 (Deep Learning Classifier Evaluation):} Evaluated 22 pure 2D model architecture combinations in \texttt{modelBenchmark/}\linebreak[1]\texttt{benchmark\_engine.py} using 5-fold cross-validation, measuring Precision, Recall, F1-Score, and runtime latency.
    \item \textbf{Phase 2 (Feature and Window Size Ablation):} Tested temporal window lengths ($W \in \{1, 3, 5, 7, 9\}$), stride values, scale normalization ($L_{\text{hand}}$ versus raw features), and CPU execution performance across various video resolutions.
    \item \textbf{Phase 3 (Tracking and Homography Accuracy):} Evaluated AprilTag corner detection accuracy, sub-pixel fitting, and planar homography reprojection error across camera tilt angles from $0^\circ$ to $75^\circ$.
    \item \textbf{Phase 4 (Real-Time Pipeline Latency and Macro Action Evaluation):} Evaluated end-to-end system throughput, latency breakdowns across pipeline components, key hit recognition performance, macro command trigger execution, and multi-profile action multiplexing.
\end{enumerate}

\subsection{Evaluation of MediaPipe Landmark Subsets and Kinematic Information Content}
\label{subsec:test_landmark_ablation}
The main empirical question in terms of designing the monocular touch detection system is determining which points among the 21 MediaPipe hand landmarks carry the most discriminative information and how different feature representations affect performance.

\subsubsection{Anatomical Landmark Groupings and Information Value}
Analysis of the 21 hand joints extracted by the MediaPipe pipeline was carried out across three functional anatomical groups:
\begin{enumerate}
    \item \textbf{Fingertip Terminals (Landmarks 4, 8, 12, 16, 20):} The terminal fingertips make direct physical impact with the paper desk surface. The sharp decrease in vertical velocity ($V_y \to 0$) serves as the primary impact trigger. However, tracking fingertips in isolation lacks the spatial context of whole-hand motion.
    \item \textbf{Interphalangeal Joints (DIP: 3, 7, 11, 15, 19 and PIP: 2, 6, 10, 14, 18):} The intermediate knuckle joints capture finger curvature and flexion angles. As a finger strikes a key, the angle between the MCP, PIP, and DIP joints changes sharply. This helps the network differentiate between an intentional finger curl and a passive downward translation of the entire hand.
    \item \textbf{Metacarpophalangeal Knuckles (MCP: 1, 5, 9, 13, 17) and Wrist (Landmark 0):} The base knuckles and wrist landmark establish the local coordinate frame for the hand. Landmark 0 (Wrist) serves as the origin $(0, 0)$ for translation invariance, while Landmark 9 (Middle MCP) provides the reference distance for hand length $L_{\text{hand}} = \|\mathbf{P}_9 - \mathbf{P}_0\|_2$ to normalize feature values.
\end{enumerate}

\subsubsection{Key Insights on Landmark Data Value and Architecture Performance}
The empirical results reveal three fundamental observations regarding model behavior:
\begin{itemize}
    \item \textbf{Why Absolute Positions Alone Fail:} Training models purely on spatial coordinates without velocity vectors yields low accuracy ($F1 = 0.798$). In a 2D camera view, the position of a finger hovering $2\text{ mm}$ above the paper appears nearly identical to that of a finger touching the paper. Without velocity, the model cannot identify the physical deceleration boundary.
    \item \textbf{Why Velocities and Scale Normalization are Essential:} Introducing first-order temporal velocity vectors ($\mathbf{V}_i = \Delta \mathbf{P}^{\text{norm}} / \Delta t$) directly exposes the physical impact deceleration spike ($V_y \to 0$), increasing the F1-score to $0.963$.
    \item \textbf{Full Skeleton vs. Fingertip-Only Subsets:} While using only the fingertip subset achieves acceptable accuracy ($F1 = 0.868$), using the full 21-joint skeleton ($F1 = 0.963$) allows the recurrent LSTM to compare relative finger movement against the palm base, eliminating false triggers caused by whole-hand repositioning.
\end{itemize}

\subsubsection{CPU Thread Memory Contention and Mutex Overhead Analysis}
Profiling Application 2 Component B confirmed that the multi-threaded queue approach effectively isolates camera image capture from PyTorch LSTM deep learning inference. Average mutex lock acquisition (\texttt{QMutex.lock()}) was $0.042$~ms per cycle, accounting for less than $0.15\%$ of total pipeline latency.

Because PyTorch LSTM forward passes run on pre-allocated tensor memory, no memory contention issues occurred between OpenCV frame decoding and PyTorch inference. No thread deadlocks or race conditions were detected during extended test runs.

\subsection{Macro Command Trigger Execution and Multi-Profile Action Benchmark}
\label{subsec:test_user_typing}
To evaluate the system as an auxiliary macro action controller, empirical testing was conducted across touch contact detection, planar key resolution, and end-to-end command execution:
\begin{enumerate}
    \item \textbf{Touch Contact Detection Reliability:} On the held-out test dataset of 636 temporal window sequences (\texttt{test\_dataset.csv}), the PyTorch LSTM sequence model achieved a touch detection accuracy of $94.34\%$ and an F1-score of $94.37\%$ ($302$ True Positives and $298$ True Negatives). False activations were limited to $20$ instances ($6.29\%$ false trigger rate on non-touch frames), confirming that the hand transit movement filter effectively suppresses false key triggers when the user repositions their hand across keys.
    \item \textbf{Planar Key Mapping Accuracy:} Planar homography estimation ($H$) demonstrated sub-millimeter reprojection accuracy ($e_{\text{rms}} \le 0.42\text{ mm}$ for camera tilts up to $60^\circ$). Because the digital layout boundaries are pre-saved in XML, key bounding box lookup requires only $0.18\text{ ms}$, ensuring accurate key selection even on compact A4 paper layouts.
    \item \textbf{Real-Time Command Dispatch Latency:} From physical finger impact on the paper to OS keystroke or shell command dispatch, the complete multi-threaded pipeline executes in $29.09\text{ ms}$ ($34.4\text{ FPS}$). This leaves a comfortable $+54.24\text{ ms}$ margin ($65.1\%$ headroom) within the $83.33\text{ ms}$ budget at 12~FPS, completely eliminating the need for artificial dwell-time delays.
    \item \textbf{Functional Test Suite Pass Rate:} All ten functional test cases (FT-01 to FT-10, Table~\ref{tab:functional_test_cases}) achieved a $100\%$ pass rate, validating key placement, XML and PDF exports, AprilTag homography, single-finger macro contact across all five digits, and virtual keystroke dispatch.
    \item \textbf{Decoupled Action Profile Multiplexing:} Testing verified that a single physical printed paper sheet can be dynamically bound to multiple distinct software action profiles (such as developer shortcuts, audio DAW controls, or terminal commands) by switching configuration files in Application~2, without reprinting the paper.
\end{enumerate}
