\section{Chapter Overview}
\label{sec:concl_overview}
This chapter summarizes the main findings, technical achievements, practical lessons, and future possibilities of the customizable paper virtual keyboard system. Using only a single standard monocular webcam and plain printed paper (without specialized hardware such as depth cameras, Time-of-Flight sensors, laser projectors, or wearable gloves) and running in real time on standard commodity CPUs, this project shows that everyday paper sheets can be turned into customizable virtual input devices across standard and low-cost camera resolutions.

Reviewing the research journey involves checking how the original goals were met, analyzing technical problems encountered during development, reflecting on skills and insights gained, discussing real-world applications, and suggesting directions for future work. Section~\ref{sec:concl_objectives} evaluates the achievement of each research objective by comparing literature review, software engineering, and experimental testing results. Section~\ref{sec:concl_problems} discusses major technical problems faced and their solutions. Section~\ref{sec:concl_reflection} presents personal self-reflections on technical learning and project insights. Section~\ref{sec:concl_business} discusses practical deployment opportunities and business use cases. Finally, Section~\ref{sec:concl_future} outlines recommendations for future research.

\section{Accomplishment of Research Objectives}
\label{sec:concl_objectives}
To verify the results of this research, a triangulation strategy was used. Triangulation links the empirical testing findings (Chapter~\ref{ch:testing_evaluation}) back through the implementation modules (Chapter~\ref{ch:implementation}) and requirements specifications (Chapter~\ref{ch:system_requirements}) to the original research objectives stated in Chapter~\ref{ch:introduction}.

\subsection{Triangulation Evaluation of Objective 1: Problem Identification and Literature Review}
\label{subsec:concl_obj1}
\begin{itemize}
    \item \textbf{Objective Statement:} \emph{To identify existing limitations in monocular vision-based virtual keyboards and synthesize a comprehensive literature taxonomy.}
    \item \textbf{Triangulation Evidence:} Chapter~\ref{ch:literature_review} reviewed 54 peer-reviewed publications, creating a structured taxonomy and comparison matrix. The review identified four key research gaps in previous literature \cite{ReviewVirtualKeyboard2020, Ji2018Local, Posner2012Single}: (1) dependence on expensive specialized hardware (depth sensors, ToF cameras, active laser projectors) or high-end GPUs, (2) monocular depth ambiguity when fingers hover above flat surfaces, (3) sensitivity to hand size and camera distance variations, and (4) lack of dynamic layout customization on plain printed paper.
    \item \textbf{Validation Outcome:} \textbf{Objective Fully Accomplished.} The literature taxonomy directly guided the system architecture and requirements in Chapter~\ref{ch:system_requirements}.
\end{itemize}

\subsection{Triangulation Evaluation of Objective 2: Scale Normalization and Deep Learning Pipeline}
\label{subsec:concl_obj2}
\begin{itemize}
    \item \textbf{Objective Statement:} \emph{To design and implement a scale-invariant hand feature extraction pipeline and a temporal PyTorch deep learning classifier for touch contact detection.}
    \item \textbf{Triangulation Evidence:} Chapter~\ref{ch:implementation} implemented the Partition 2 Data Pipeline and Partition 3 Deep Learning Benchmark Engine. Hand joint coordinates were scale-normalized using unitless hand length ($L_{\text{hand}} = \|\mathbf{P}_9 - \mathbf{P}_0\|_2$), and sliding windows of 5 frames with 2-frame overlap ($\mathbf{X}_W \in \mathbb{R}^{5 \times 84}$) were constructed at a 12~FPS standard rate. Scale-normalized features were passed directly to preserve clear deceleration signals during contact. Benchmark tests in Chapter~\ref{ch:testing_evaluation} showed that the uni-directional PyTorch LSTM model (\texttt{best\_finger\_touch\_lstm.pth}) achieved an F1-score of $0.963$ with a fast CPU inference time of $2.08\text{ ms}$.
    \item \textbf{Validation Outcome:} \textbf{Objective Fully Accomplished.} Testing confirmed distance invariance ($F1 \ge 0.958$ across $Z \in [30\text{ cm}, 100\text{ cm}]$) and camera resolution invariance ($F1 \in [0.961, 0.964]$ across 360p to 1080p) running in real time on standard commodity CPUs without a GPU.
\end{itemize}

\subsection{Triangulation Evaluation of Objective 3: System Suite Design and Engineering}
\label{sec:concl_obj3}
\begin{itemize}
    \item \textbf{Objective Statement:} \emph{To design and implement an integrated two-application software suite enabling arbitrary custom layout design and decoupled action combination multiplexing on the same printed paper layout.}
    \item \textbf{Triangulation Evidence:} Chapter~\ref{ch:implementation} built Application 1 Layout Designer (\texttt{designer/designer\_app.py}) and Application 2 Runtime Engine. Application 1 provides a PySide6 drag-and-drop canvas, automatic AprilTag border placement, XML layout export, and 300 DPI vector PDF generation for custom layouts. Application 2 provides a Setup GUI (Component A) for assigning key IDs to keystrokes or shell commands with full support for saving and switching multiple JSON action profiles on the exact same printed paper sheet without reprinting, and a background engine (Component B) running video capture, AprilTag homography tracking, PyTorch LSTM inference, and coordinate mapping ($P_{\text{XML}} = H \cdot P_{\text{pixel}}$).
    \item \textbf{Validation Outcome:} \textbf{Objective Fully Accomplished.} Functional testing in Chapter~\ref{ch:testing_evaluation} demonstrated a $100\%$ pass rate across all ten test cases (FT-01 through FT-10), confirming that the same printed layout can trigger different action profiles through software configuration.
\end{itemize}

\subsection{Triangulation Evaluation of Objective 4: Empirical System Evaluation}
\label{subsec:concl_obj4}
\begin{itemize}
    \item \textbf{Objective Statement:} \emph{To conduct rigorous empirical benchmarking evaluating real-time pipeline latency, optical homography tracking, and human typing performance.}
    \item \textbf{Triangulation Evidence:} Chapter~\ref{ch:testing_evaluation} evaluated the integrated system on standard CPU hardware. The multi-threaded engine achieved an end-to-end processing latency of $29.09\text{ ms}$ ($34.4\text{ FPS}$) with low resource usage ($142.5\text{ MB}$ RAM, $24.8\%$ CPU load), easily fitting within the 12~FPS budget ($83.33\text{ ms}$). AprilTag homography tracking maintained an RMS error under $0.42\text{ mm}$ for camera tilt angles up to $60^\circ$. User typing tests showed an average typing speed of $24.6\text{ WPM}$ with a Character Error Rate of $5.2\%$.
    \item \textbf{Validation Outcome:} \textbf{Objective Fully Accomplished.} The system outperformed previous single-camera virtual keyboards in published literature ($12.8\text{ WPM}$, $11.4\text{ CER}$ \cite{Ji2018Local}).
\end{itemize}

\section{Problems Encountered and Technical Mitigations}
\label{sec:concl_problems}
During the design, implementation, and evaluation of the system, several practical problems arose from optical camera limitations and user interaction dynamics.

\subsection{Hardware Constraints of Monocular RGB Capture}
Standard webcams operate at $30\text{ FPS}$ with rolling shutter sensors, which can introduce motion blur during fast finger taps \cite{Thomas2013Camera}. When a user types quickly, fast downward finger motion can cause landmark tracking confidence to drop momentarily.
\begin{itemize}
    \item \textbf{Technical Mitigation:} A 12~FPS resampling script (\texttt{resample\_12fps.py}) was used during dataset creation, training the PyTorch LSTM model on lower-frame-rate inputs. As a result, the model handles frame jitter and slight motion blur effectively during live camera execution.
\end{itemize}

\subsection{Ambient Environmental Lighting and Shadow Variations}
Monocular landmark tracking and AprilTag detection are sensitive to sudden lighting changes, strong directional shadows, and uneven glare \cite{ReviewVirtualKeyboard2020}. Harsh sunlight casting dark finger shadows on the paper can distort corner detection.
\begin{itemize}
    \item \textbf{Technical Mitigation:} The AprilTag detector (\texttt{aprilTag/estimater.py}) applies adaptive thresholding to grayscale frames before quad extraction. In addition, the SVD homography solver needs only four unoccluded tag corners across the page margins to maintain accurate mapping.
\end{itemize}

\subsection{Anatomical Finger Co-articulation}
Human fingers naturally share tendons, especially between the ring finger and pinky finger. When pressing a key with the ring finger, the pinky finger often moves downward slightly as well, which could trigger unwanted touches.
\begin{itemize}
    \item \textbf{Technical Mitigation:} The PyTorch LSTM model predicts probabilities for all five fingers simultaneously using multi-label Binary Cross-Entropy loss ($\mathcal{L}_{\text{BCE}}$). This allows the network to distinguish primary intentional key strikes from minor secondary finger movements.
\end{itemize}

\subsection{Absence of Tactile Haptic Surface Feedback}
Tapping on flat paper provides no mechanical key travel or switch click sound. During initial tests, users were sometimes unsure if a key press had registered, causing them to press harder.
\begin{itemize}
    \item \textbf{Technical Mitigation:} Immediate visual and audio feedback were added to Application 2 Component B. When a touch is confirmed ($p_k > 0.90$), the software plays a short click sound ($< 5\text{ ms}$ latency) and briefly flashes a green box over the pressed key on the live screen overlay.
\end{itemize}

\section{Self-Reflection}
\label{sec:concl_reflection}
Working on this research provided valuable academic and engineering experience in computer vision, deep learning, and software architecture.

\subsection{Ideology Regarding Paper-Based Touch Interaction}
Before starting this research, I assumed virtual input devices required expensive hardware, such as laser projectors, Time-of-Flight sensors, or electronic gloves. However, studying monocular computer vision and homography geometry showed that smart software design can replace complex hardware. By combining a regular sheet of printed paper with a standard webcam and a lightweight PyTorch LSTM model running on a regular CPU without requiring a GPU, a working virtual input interface can be built at near-zero hardware cost. This experience highlighted how software-driven physical interfaces can help make computing input more accessible in low-resource environments.

\subsection{Technical Benefits Gained Across Engineering Domains}
This project provided hands-on experience across four main computer science areas:
\begin{enumerate}
    \item \textbf{Applied Computer Vision and Geometry:} Gained practical experience in camera calibration ($K$), lens distortion correction ($\mathbf{D}$), AprilTag fiducial tracking, Direct Linear Transformation (DLT), and Singular Value Decomposition (SVD) for Planar Homography ($H \in \mathbb{R}^{3 \times 3}$).
    \item \textbf{Deep Learning for Temporal Signals:} Learned how to design and train PyTorch recurrent models, build multi-model benchmark pipelines (\texttt{run\_all.py}), apply unitless scale normalization ($L_{\text{hand}}$), and format sliding temporal windows ($\mathbf{X}_W \in \mathbb{R}^{5 \times 84}$).
    \item \textbf{Concurrent Multi-Threaded Programming:} Designed a producer-consumer thread system in PySide6 (\texttt{QThread}, \texttt{QMutex}, \texttt{QWaitCondition}), separating video capture from neural network inference to prevent frame drops and keep real-time throughput ($34.4\text{ FPS}$).
    \item \textbf{Academic Research and Documentation:} Developed skills in systematic testing, measuring typing metrics (WPM, CER), structuring research chapters, and writing formal LaTeX documentation with IEEE citations.
\end{enumerate}

\subsection{Critical Learning Curves and Methodological Reflections}
\label{subsec:concl_learning_curves}
A key learning curve in this project was balancing computing load with responsive touch detection on standard consumer computers. Early thoughts were to use high frame rates ($30\text{--}60$~FPS) and heavy neural networks, which would have required expensive GPUs and restricted the system from running on everyday laptops.

Through testing and profiling, it became clear that standardizing the pipeline at 12~FPS provides the right balance: it gives enough temporal detail to detect touch deceleration while leaving an ample $83.33\text{ ms}$ frame budget. This lightweight design allows the entire vision and deep learning pipeline to run smoothly on a standard CPU without a GPU, taking only $29.52\text{ ms}$ per frame. Combining this with unitless hand scale normalization and SVD homography mapping also ensures that low-resolution cameras (such as 360p or 480p) achieve the same touch accuracy ($F1 \approx 0.963$) as higher-end cameras.

\section{Business Insights and Real-World Application Possibilities}
\label{sec:concl_business}
The paper virtual keyboard system offers practical advantages over traditional hardware keyboards, including low cost, custom layouts, easy cleaning, and quick deployment across different settings.

\subsection{Sterile Medical Operating Rooms and Clinical Environments}
In hospital operating rooms and clinics, physical keyboards and touchscreens can harbor bacteria because physical keys are difficult to disinfect between patients. A paper virtual keyboard printed on laminated, waterproof paper can be wiped clean with disinfectant or replaced for pennies per sheet, providing a clean input surface for medical staff.

\subsection{Industrial Cleanrooms and Hazardous Chemical Laboratories}
Semiconductor cleanrooms and chemical laboratories require spark-free, non-hazardous equipment. Electronic devices can accumulate dust or produce electrical sparks. A printed paper layout with AprilTag markers is completely passive and requires no electrical power on the table, making it safe to use in sensitive environments.

\subsection{Low-Cost Educational Classrooms in Developing Regions}
Schools in low-resource communities often lack funds for computer accessories and replacement keyboards. Using Application 1 Layout Designer (\texttt{designer\_app.py}), teachers can print custom keyboard layouts, piano pads, or learning sheets on standard A4 paper. Connected to a single computer and basic webcam, students can interact with educational programs through paper interfaces.

\subsection{Customized Digital Audio Workstations and Accessibility Interfaces}
Hardware macro pads and MIDI controllers for software applications (such as digital audio workstations like Ableton Live, video editors like Adobe Premiere, or CAD software) are expensive and have fixed physical keys. Application 2 allows users to use a single printed sheet of paper and switch between multiple action profiles (such as a recording profile, an editing profile, and a mixing profile) in software without reprinting the sheet. In addition, users with motor impairments can design custom large-button accessibility layouts suited to their physical mobility, switching between speech tools, navigation shortcuts, and text input on the same printed layout.

\section{Future Recommendations}
\label{sec:concl_future}
While the virtual keyboard system performs reliably, there are several promising directions for future research:

\subsection{Integration of Monocular Neural Depth Models}
Future work could explore adding lightweight monocular depth estimation models (such as Depth Anything or MiDaS-nano) directly to the pipeline. Combining 2D hand joint coordinates with estimated depth maps could provide millimeter-level Z-axis distance data, further improving touch contact classification.

\subsection{Multi-Camera Stereo Vision Fusion}
Extending the single-camera setup to a dual-camera stereo configuration would help resolve hand occlusion. Tracking hand joints from two different angles would provide 3D triangulation and keep tracking active even when one camera view is partially blocked.

\subsection{Two-Handed (Bimanual) Typing with Dual Window Buffering}
While the current system implementation is optimized for single-handed active typing to ensure low CPU computation time and avoid fiducial marker occlusion on compact A4 paper sheets, the underlying modular architecture can be expanded to support two hands. Future research can configure MediaPipe for two hands (\texttt{num\_hands=2}) and run separate 5-frame sliding window buffers for both the left and right hands. With the lightweight PyTorch model taking only $2.08\text{ ms}$ per forward pass, dual-hand inference would take approximately $33\text{ ms}$ total on CPU, remaining well within the $83.33\text{ ms}$ 12~FPS frame budget.

\subsection{Spatial Acoustic and Ultrasonic Mid-Air Haptic Feedback}
To provide physical feeling without mechanical keys, future versions could incorporate ultrasonic mid-air haptic arrays. By focusing ultrasonic pressure waves onto the active fingertip when a key press is confirmed, users could feel physical tactile feedback in the air.

\subsection{Deep Learning Based Fiducial Marker Tracking}
While classical AprilTag 2/3 detection operates efficiently on CPU, future research could explore integrating lightweight convolutional marker detectors like DeepTag \cite{Zhang2022DeepTag}. By estimating dense keypoints directly through neural networks, such approaches could provide even greater homography stability under severe motion blur or heavy finger occlusions.

\subsection{Transformer-Based Temporal Self-Attention Architectures}
Although the PyTorch uni-directional LSTM model achieved strong results ($F1 = 0.963$), testing lightweight temporal Transformer models could help capture longer sequential patterns, potentially reducing Character Error Rates during fast, continuous typing.

\section{Chapter Summary}
\label{sec:concl_summary}
This chapter concluded the thesis by reviewing the achievement of research objectives, discussing problems and mitigations, reflecting on technical lessons, presenting business use cases, and outlining future research directions.

The research demonstrated that a customizable paper virtual keyboard powered by monocular computer vision, hand scale normalization ($L_{\text{hand}}$), AprilTag planar homography ($H \in \mathbb{R}^{3 \times 3}$), and PyTorch temporal deep learning (\texttt{best\_finger\_touch\_lstm.pth}) achieves reliable, real-time typing performance ($29.09\text{ ms}$ latency, $34.4\text{ FPS}$, $24.6\text{ WPM}$) on standard commodity CPU hardware. By replacing specialized hardware with smart software engineering, this work provides a flexible, hygienic, and accessible input interface.
