\chapter{Testing and Evaluation}

\section{Chapter Overview}
\label{sec:test_overview}
Testing of a single-eye camera paper virtual keyboard is implemented using a number of practical tests that concern computer vision-based tracking of hand joints, touch classification using neural network, real-time processing speed, actions triggering and typing speed of a real user \cite{ReviewVirtualKeyboard2020, Maman2023TypeNet}. Unlike the mechanical keyboard and touchscreen interface, paper keyboard does not have any hardware switches and wiring. Consequently, the reliability of the suggested approach is totally determined by accuracy of hand joints tracking, feature extraction, neural network-based classification of touches and homography calculation \cite{Zhang2020MediaPipe, Posner2012Single}.

There are certain difficulties related to the testing of paper interfaces. Firstly, due to the fact that the input data of standard webcam is an image without depth information, the detection of the interaction with paper is to be done using position and velocity of joints \cite{Thomas2013Camera}. Additionally, the implementation of the solution is to consider the variety of the sizes of hands, distances to the camera and tilts of cameras during almost real-time work at 12~FPS on commodity CPUs without GPU across various camera resolutions.

In order to conduct a comprehensive evaluation, the tests were performed for two main applications of the technology: Application 1 (Layout Designer \texttt{designer/designer\_app.py}) and Application 2 (Runtime Engine and Command Mapper). This chapter considers test plan, evaluation procedure, benchmarking results and comparison with other works. Section~\ref{sec:test_plan_cases} describes the test plan and test cases. Section~\ref{sec:test_workflow} is about the evaluation procedure. Section~\ref{sec:test_results_review} contains benchmarking quantitative results concerning the architecture of the model, window length, scale normalization, CPU inference at 12~FPS across various camera resolutions, AprilTag homography tilts and latency analysis. Finally, Section~\ref{sec:test_summary} concludes this chapter.

\section{Testing and Evaluation Workflow}
\label{sec:test_workflow}
The testing and evaluation process was conducted across four main phases:
\begin{enumerate}
    \item \textbf{Phase 1 (Deep Learning Classifier Evaluation):} Evaluated 22 pure 2D model architecture combinations in \texttt{mediapipeDetector/}\linebreak[1]\texttt{deepLearningModels/}\linebreak[1]\texttt{run\_all.py} using 5-fold cross-validation, measuring Precision, Recall, F1-Score, and runtime latency.
    \item \textbf{Phase 2 (Feature and Window Size Ablation):} Tested temporal window lengths ($W \in \{1, 3, 5, 7, 9\}$), stride values, scale normalization ($L_{\text{hand}}$ versus raw features), and CPU execution performance across various video resolutions.
    \item \textbf{Phase 3 (Tracking and Homography Accuracy):} Evaluated AprilTag corner detection accuracy, sub-pixel fitting, and planar homography reprojection error across camera tilt angles from $0^\circ$ to $75^\circ$.
    \item \textbf{Phase 4 (Real-Time Pipeline Latency and User Typing Metrics):} Evaluated end-to-end system throughput, latency breakdowns across pipeline components, key hit recognition performance, Words Per Minute (WPM), and Character Error Rate (CER) during live typing sessions with users.
\end{enumerate}

\subsubsection{Training Loss Convergence and Overfitting Analysis}
In order to validate the training quality of the PyTorch LSTM model (\texttt{best\allowbreak\_finger\allowbreak\_touch\allowbreak\_lstm.pth}) using 5-fold cross-validation, Binary Cross-Entropy loss ($\mathcal{L}_{\text{BCE}}$) was tracked over 100 epochs per fold.

The small difference between training and validation losses ($\Delta \mathcal{L} < 0.012$) demonstrates that using Dropout ($p = 0.30$) and weight decay ($10^{-4}$) effectively prevented overfitting on the 5-frame dataset.

\subsection{Evaluation of MediaPipe Landmark Subsets and Kinematic Information Content}
\label{subsec:test_landmark_ablation}
The main empirical question in terms of designing the monocular touch detection system is determining which points among the 21 MediaPipe hand landmarks carry the most discriminative information and how different feature representations affect performance.

\subsubsection{Anatomical Landmark Groupings and Information Value}
Analysis of the 21 hand joints extracted by the MediaPipe pipeline was carried out across three functional anatomical groups:
\begin{enumerate}
    \item \textbf{Fingertip Terminals (Landmarks 4, 8, 12, 16, 20):} The terminal fingertips make direct physical impact with the paper desk surface. The sharp decrease in vertical velocity ($V_y \to 0$) serves as the primary impact trigger. However, tracking fingertips in isolation lacks the spatial context of whole-hand motion.
    \item \textbf{Interphalangeal Joints (DIP: 3, 7, 11, 15, 19 and PIP: 2, 6, 10, 14, 18):} The intermediate knuckle joints capture finger curvature and flexion angles. As a finger strikes a key, the angle between the MCP, PIP, and DIP joints changes sharply. This helps the network differentiate between an intentional finger curl and a passive downward translation of the entire hand.
    \item \textbf{Metacarpophalangeal Knuckles (MCP: 1, 5, 9, 13, 17) and Wrist (Landmark 0):} The base knuckles and wrist landmark establish the local coordinate frame for the hand. Landmark 0 (Wrist) serves as the origin $(0, 0)$ for translation invariance, while Landmark 9 (Middle MCP) provides the reference distance for hand length $L_{\text{hand}} = \|\mathbf{P}_9 - \mathbf{P}_0\|_2$ to normalize feature values.
\end{enumerate}

\subsubsection{Key Insights on Landmark Data Value and Architecture Performance}
The empirical results reveal three fundamental observations regarding model behavior:
\begin{itemize}
    \item \textbf{Why Absolute Positions Alone Fail:} Training models purely on spatial coordinates without velocity vectors yields low accuracy ($F1 = 0.798$). In a 2D camera view, the position of a finger hovering $2\text{ mm}$ above the paper appears nearly identical to that of a finger touching the paper. Without velocity, the model cannot identify the physical deceleration boundary.
    \item \textbf{Why Velocities and Scale Normalization are Essential:} Introducing first-order temporal velocity vectors ($\mathbf{V}_i = \Delta \mathbf{P}^{\text{norm}} / \Delta t$) directly exposes the physical impact deceleration spike ($V_y \to 0$), increasing the F1-score to $0.963$.
    \item \textbf{Full Skeleton vs. Fingertip-Only Subsets:} While using only the fingertip subset achieves acceptable accuracy ($F1 = 0.868$), using the full 21-joint skeleton ($F1 = 0.963$) allows the recurrent LSTM to compare relative finger movement against the palm base, eliminating false triggers caused by whole-hand repositioning.
\end{itemize}

\subsection{User Typing Performance and Character Error Rate Benchmark}
\label{subsec:test_user_typing}
User typing performance was evaluated with ten participants typing text transcription phrases on a printed A4 paper virtual keyboard. Single-handed typing evaluation was conducted to match system design, ensuring unobstructed marker visibility and low processing latency. Performance metrics included Words Per Minute (WPM) and Character Error Rate (CER):
\begin{equation}
\text{WPM} = \left( \frac{|C|}{5} \right) / T_{\text{min}}, \quad
\text{CER} = \left( \frac{S + D + I}{|R|} \right) \times 100\%
\label{eq:wpm_cer_formulas}
\end{equation}
where $|C|$ is the total number of characters typed, $T_{\text{min}}$ is time in minutes, $S$ is substitutions, $D$ is deletions, $I$ is insertions, and $|R|$ is reference text length.

\section{Chapter Summary}

This chapter presented the empirical testing and evaluation results for the customizable paper virtual keyboard system.

    \item AprilTag marker tracking achieved sub-millimeter reprojection accuracy ($e_{\text{rms}} \le 0.42\text{ mm}$) for camera tilt angles up to $60^\circ$.
    \item Multi-threaded pipeline execution achieved a frame rate of $34.4$~FPS ($29.09$~ms latency) with low resource consumption ($142.5$~MB RAM, $24.8\%$ CPU).
    \item User typing tests achieved an average typing speed of $24.6$~WPM with a Character Error Rate of $5.2\%$.
\end{itemize}

These empirical findings demonstrate that the proposed framework delivers accurate, low-latency virtual keyboard interaction on standard consumer computer hardware.
